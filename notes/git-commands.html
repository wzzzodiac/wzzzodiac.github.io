NOTE 006 // GIT

Git commands I refuse to memorize twice

Only the normal commands: inspect first, change something deliberately, commit one finished technical change, then push.

01

Inspect before touching anything

git status
git status -sb
git diff

status shows changed, staged and untracked files. -sb gives a compact branch/status view. diff shows the actual unstaged line changes.

02

Get a repository

git clone <repository>
git pull

clone creates a local copy. pull brings the current remote branch into the local branch before new work.

03

Authenticate to GitHub over HTTPS

If the remote starts with https://github.com/..., GitHub does not accept the account password for Git operations. Use the GitHub username plus a personal access token when Git asks for credentials.

Create the token in GitHub under Settings → Developer settings → Personal access tokens. Give it only the repository access/permissions actually needed. Copy it when GitHub shows it; treat it like a password and never commit it into a repository.

git push

Username: YOUR-GITHUB-USERNAME
Password: YOUR-PERSONAL-ACCESS-TOKEN

The token is entered in the password field. The terminal may show no characters while you paste/type it; that is normal.

04

Make HTTPS login stay remembered

The preferred route is GitHub CLI or Git Credential Manager instead of saving a token manually in plain text.

gh auth login

Choose GitHub.com → HTTPS and allow GitHub CLI to authenticate Git. After the browser/login flow, normal git pull and git push can reuse the stored credentials.

On Windows, modern Git for Windows normally includes Git Credential Manager. After successful browser authentication it stores the credential in Windows Credential Manager, so Git should stop asking every time.

Do not use credential.helper store casually: it can save the token unencrypted on disk. Use GitHub CLI, Git Credential Manager, or SSH instead.

05

Check which authentication method the repo uses

git remote -v

If the remote begins with https://github.com/, the HTTPS/token or credential-manager instructions apply. If it begins with git@github.com:, the repository uses SSH instead.

06

Stage and commit

git add .
git commit -m "Short description"
git push

add stages selected changes. commit records that state locally. push sends committed work to the remote repository.

07

Branches

git branch
git switch <branch>
git switch -c <new-branch>

branch lists local branches. switch changes branch. switch -c creates and enters a new one.

08

History and differences

git log --oneline
git diff --staged

log --oneline gives a compact commit history. diff --staged shows exactly what the next commit will contain.

09

Check another repository without changing directory

git -C <path> status -sb

-C tells Git to operate in another directory. This was useful when the Docker infrastructure and processing code lived in separate repositories.

10

SSH sanity check

ssh -T git@github.com

Checks whether GitHub recognizes the configured SSH key. It does not push anything. SSH is also a good permanent alternative to HTTPS tokens once the key is configured.

My normal workflow

  • git status
  • git diff
  • test the change
  • git add .
  • git diff --staged
  • git commit -m "..."
  • git push
