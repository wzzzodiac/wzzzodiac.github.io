NOTE 005 // RASPBERRY PI / BA FIELD LOG

Raspberry Pi field setup

The short recovery path distilled from the real LiDAR/ROS 2 setup: power, display, network, Docker and the checks that actually solved problems.

Order matters

Do not start with RViz. First verify hardware, network, container, ROS graph and data flow. Visualization comes last.

01

Power and display

The Pi 5 rejected an ordinary phone charger as inadequate. Use a correctly specified Pi 5 USB-C supply. For display, remember that the Pi outputs Micro-HDMI; adapters belong between Pi and monitor, not Pi and PC.

02

Check the host network

ip -brief address
nmcli connection show
ping -c 4 <DEVICE-IP>

ip -brief address shows interface state and addresses. nmcli connection show shows NetworkManager connections. ping checks whether the device is actually reachable.

03

Check Docker before ROS

docker ps
cd ~/ros2_docker_ws
docker compose up -d

docker ps confirms the main container is running. docker compose up -d starts or recreates the configured service when needed.

04

Enter and build the workspace

~/ros2_docker_ws/scripts/enter.sh
~/ros2_docker_ws/scripts/build.sh

The scripts hide the long Docker and colcon commands and keep the development environment reproducible.

05

Start the data path in order

Driver first, processing node second, RViz last. A running process is not proof that messages are moving.

driver
nodo
rviz
06

If RViz sees a topic but no cloud

One real failure came from different IPC namespaces between the main Docker container and the temporary RViz container. The durable fix was host networking plus host IPC on both sides. A second failure was QoS incompatibility: the LiDAR input stayed SensorDataQoS while processed outputs were changed to Reliable + Volatile.

07

Known graphical boot problem

When the Ubuntu desktop intermittently froze after login, disabling Wayland and using Xorg made startup reliable. The short black screen and X-shaped cursor during Xorg startup were accepted as normal startup behavior, not LiDAR processing latency.

Recovery order

  • Correct power.
  • Ethernet/interface address.
  • Ping sensor/device.
  • Docker container running.
  • Driver starts.
  • ROS topic exists and messages arrive.
  • Processing node and outputs exist.
  • Only then open RViz.
