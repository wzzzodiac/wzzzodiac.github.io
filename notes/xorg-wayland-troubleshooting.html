NOTE 016 // UBUNTU / DISPLAY

Xorg vs Wayland troubleshooting

A note for one very specific problem we actually hit: Ubuntu login/display startup on the Raspberry Pi becoming unreliable under the original graphical setup.

01

The symptom

After login, the desktop could freeze or fail to appear correctly. Restarting helped, but the behavior was not reproducible enough for a research system.

02

The practical change

Wayland was disabled so the desktop started with Xorg instead. After that, startup became consistently usable in the tested setup.

03

What the strange startup looked like

A short black screen followed by an X-shaped mouse cursor appeared before the normal desktop. In this setup that was simply part of the Xorg startup sequence.

04

What it did not mean

The different graphical startup was not treated as extra runtime latency for the LiDAR pipeline. Desktop startup behavior and the later ROS/PCL processing path are separate issues.

05

Why this note exists

Do not change display servers just because Xorg or Wayland is universally “better”. In this case the change was kept because it solved a concrete, repeated login problem on the actual machine.
