NOTE 002 // GIT

Clone a repository and pull updates

The short workflow for downloading a GitHub repository once and keeping the local folder updated later.

Remember

git clone = first download. git pull = update the copy you already cloned.

01

First time: clone the repository

Open PowerShell and go to the folder where the repository should be stored.

cd "C:\path\where\you\want\it"

On GitHub, open the repository, press Code, select HTTPS and copy the URL. Then run:

git clone https://github.com/OWNER/REPOSITORY.git

Git creates a new folder containing the entire repository.

02

Later: pull the newest changes

Open PowerShell inside the cloned repository folder, or move into it:

cd "C:\path\to\REPOSITORY"

Then run:

git pull

Git downloads the newest changes into that local folder. Do not clone the repository again every time.

03

If the repository is private

Your GitHub account must have access to the repository. Start by running the normal HTTPS clone command:

git clone https://github.com/OWNER/REPOSITORY.git

If Git opens a browser login, sign in to the GitHub account that has access and authorize Git. After that, cloning continues normally and Windows usually remembers the login for future pulls.

04

If the browser login does not appear or authentication fails

Use GitHub CLI to authenticate once:

gh auth login

Select these options:

GitHub.com
HTTPS
Login with a web browser

Follow the browser login, authorize GitHub CLI, return to PowerShell and run the clone command again.

If PowerShell says gh is not recognized, install GitHub CLI first from cli.github.com, then repeat gh auth login.

05

Do not use your normal GitHub password in the terminal

GitHub does not accept the normal account password for Git operations over HTTPS. Use the browser login / Git Credential Manager or gh auth login.

Quick version

  • First download: git clone REPOSITORY-URL.
  • Future updates: open the cloned folder and run git pull.
  • Private repo: log in with the GitHub account that has access.
  • If normal login fails: gh auth login → GitHub.com → HTTPS → web browser.
  • After successful authentication, future pulls normally do not ask again.
