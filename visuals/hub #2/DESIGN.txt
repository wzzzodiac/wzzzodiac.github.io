CORE LOOK
---------
Hub #2 is a monochrome industrial / lab-notebook interface.
Primary palette: black, charcoal, gunmetal, dirty grey, off-white.
Accent palette: very restrained cold cyan for active states, links and small indicators.
Secondary accent: warm beige paper for handwritten/physical-note elements only.
The page must NOT become uniformly dark-blue or neon-cyberpunk. Texture and contrast should come from material, light and layering rather than saturated color.

MATERIAL / TEXTURE
------------------
- Dark brushed/oxidized metal feel on page chrome and large structural panels.
- Fine technical grid in selected backgrounds, not everywhere.
- Slight scratches/noise simulated with CSS gradients and pseudo-elements where practical.
- Thin metal borders, inset highlights and restrained shadows.
- Paper notes: warm off-white, subtle grid/fibers, slightly imperfect rotation, tape-like strips.
- Small light streaks / highlights may cross metal panels to stop the interface feeling flat.
- Avoid glossy gaming-UI effects, huge glows, rainbow gradients or bright saturated panels.

LAYOUT
------
Desktop reference structure:
1. Fixed left navigation rail.
2. Thin top utility bar.
3. Main center column.
4. Narrow right information rail.
5. Hero panel at top of center column.
6. Featured project cards below hero.
7. Quick access row below projects.

The composition should feel dense but orderly, like a physical engineering workstation translated into a website.

IMPLEMENTATION REALISM
----------------------
This design must be achievable with ordinary HTML/CSS/JS and static assets on GitHub Pages.
Preferred techniques:
- CSS Grid / Flexbox
- layered gradients
- pseudo-elements for scratches/light streaks/tape
- subtle box-shadow/inset borders
- simple CSS noise-like patterns, no heavy WebGL requirement
- responsive collapse from 3-column desktop to 1-column mobile
- no framework required unless Codex can justify it

REFERENCE PREVIEW
-----------------
preview.html + preview.css are deliberately standalone and are NOT wired into the live root pages.
They are implementation scaffolding, not the final site.
The preview uses placeholders for project imagery because the hub repository currently does not contain dedicated thumbnail assets for those projects. Those placeholders should later be replaced with real screenshots/assets, not invented images.
